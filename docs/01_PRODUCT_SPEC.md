# Portfolio Platform — Product Specification

**Version:** 1.1
**Status:** Approved for development
**Document:** `docs/01_PRODUCT_SPEC.md`

---

## 1. Product Overview

Portfolio Platform — веб-сервис для создания и размещения профессионального портфолио разработчика, дизайнера или фрилансера.

Пользователь добавляет свои проекты в одном месте, оформляет их в виде профессиональных кейсов и получает публичную страницу портфолио с уникальной ссылкой.

Основная идея продукта:

> **Собрать проекты → профессионально их оформить → получить готовое портфолио → отправить одну ссылку работодателю или клиенту.**

Сервис должен быть простым, быстрым и ориентированным прежде всего на демонстрацию реальных работ.

---

## 2. Problem

Многие начинающие разработчики и фрилансеры имеют проекты, но не умеют нормально их представить.

Информация о работах обычно находится в разных местах:

* GitHub;
* отдельные сайты;
* скриншоты;
* локальные файлы;
* документы;
* сообщения;
* старые проекты.

При этом потенциальному клиенту или работодателю приходится самостоятельно разбираться:

* что было сделано;
* какую проблему решал проект;
* какие технологии использовались;
* что именно сделал исполнитель;
* есть ли рабочая демонстрация.

Обычный список ссылок на GitHub не всегда показывает ценность работы.

Portfolio Platform решает эту проблему, объединяя проекты в одном профессиональном портфолио.

## 3. Target Audience

### Основная аудитория

* Junior-разработчики;
* Middle-разработчики;
* начинающие фрилансеры;
* веб-разработчики;
* дизайнеры;
* специалисты, которые хотят показать свои проекты работодателю или клиенту.

### Приоритет MVP

В первой версии основной пользователь — **разработчик или фрилансер**.

Продукт сначала оптимизируется именно под этот сценарий.

---

## 4. Core User Scenario

Основной сценарий:

```text
Регистрация
    ↓
Создание профиля
    ↓
Добавление проекта
    ↓
Заполнение информации о проекте
    ↓
Добавление изображений / ссылок
    ↓
Добавление технологий
    ↓
Настройка порядка проектов
    ↓
Публикация портфолио
    ↓
Получение публичной ссылки
```

Пример публичной ссылки:

```text
portfolio.app/dmitriy
```

Посетитель открывает ссылку и видит:

* имя;
* профессию;
* краткое описание;
* навыки;
* проекты;
* информацию о каждом проекте;
* GitHub;
* Live Demo;
* контактные ссылки.

---

## 5. Core Product Value

Главная ценность:

> **Превратить набор разрозненных проектов в понятное профессиональное представление специалиста.**

Продукт должен отвечать на три вопроса потенциального клиента или работодателя:

### Что человек умеет?

Показывается через проекты и технологии.

### Что он реально сделал?

Показывается через описание проекта, его роль, функции и результаты.

### Где это посмотреть?

Предоставляются GitHub, Live Demo и публичное портфолио.

# 6. MVP

Первая версия должна содержать только функции, необходимые для создания полноценного портфолио.

## 6.1 Authentication

Пользователь должен иметь возможность:

* зарегистрироваться;
* войти;
* выйти из аккаунта.

---

## 6.2 Profile

Пользователь может указать:

* имя;
* username;
* фотографию;
* профессию;
* краткое описание;
* город/локацию по желанию;
* GitHub;
* Telegram;
* LinkedIn;
* другие ссылки.

---

## 6.3 Projects

Пользователь может создавать проекты.

Каждый проект содержит:

* название;
* короткое описание;
* подробное описание;
* проблему;
* решение;
* результат;
* роль пользователя;
* технологии;
* изображение/обложку;
* GitHub URL;
* Live Demo URL;
* дату;
* статус публикации.

Проекты должны иметь возможность менять порядок отображения.

---

## 6.4 Project Case Study

Проект отображается не просто как карточка.

Для каждого проекта должна существовать отдельная страница.

Структура:

```text
Project Name

Short Description

Problem
What problem did the project solve?

Solution
How was the problem solved?

My Role
What exactly did the user do?

Features
What was implemented?

Result
What was achieved?

Tech Stack
Python
FastAPI
React
PostgreSQL

Links
GitHub
Live Demo
```

Это является одной из ключевых особенностей продукта.

---

## 6.5 Public Portfolio

Каждый пользователь получает публичную страницу.

Например:

```text
portfolio.app/dmitriy
```

Страница должна содержать:

```text
Profile
    ↓
About
    ↓
Skills
    ↓
Projects
    ↓
Contacts
```

Публичная страница не должна требовать авторизации посетителя.

---

## 6.6 Portfolio Settings

Пользователь может:

* выбрать username;
* менять порядок проектов;
* публиковать/скрывать проекты;
* редактировать профиль;
* менять основные ссылки.

# 7. GitHub Integration

**Priority: P1 — реализовано и работает в продукте** (решение владельца проекта от 2026-09-16: запрет на GitHub снят, см. `docs/00_RESEARCH_METHOD.md` §4).

GitHub используется **только как источник публичных данных о репозиториях**.

Правила интеграции:

* используется публичный неавторизованный API — **без токена, без OAuth, без привязки аккаунта**;
* ничего не сохраняется автоматически: пользователь сам выбирает,
  какие репозитории превратить в проекты;
* форки не предлагаются к импорту (они не показывают оригинальную работу);
* при исчерпании лимита GitHub пользователь видит понятное сообщение.

Минимальный сценарий:

```text
GitHub Repository
       ↓
Import
       ↓
Repository information
       ↓
Create Project
       ↓
User edits information
       ↓
Publish
```

Важно:

**GitHub не должен полностью автоматически создавать готовый кейс без подтверждения пользователя.**

Пользователь контролирует итоговую информацию.

# 8. AI Features

**Priority: POST-MVP — не входит в MVP** (решение владельца проекта; см. `03_DATA_API.md` §45 и `04_DEVELOPMENT_RULES.md` §56–57).

AI является дополнительной функцией, а не основой продукта.

Главная задача AI — помочь пользователю профессионально оформить уже существующий проект.

### AI Project Assistant

Пользователь вводит черновое описание:

> Сделал Telegram-бота для проверки подписки на канал. Использовал Python и Telegram API.

AI может предложить:

* Problem;
* Solution;
* Features;
* Result;
* краткое описание;
* улучшенную формулировку проекта.

После генерации пользователь может всё изменить вручную.

---

## 8.1 AI Rules

AI не должен придумывать факты о проекте.

Если пользователь не указал:

* количество пользователей;
* процент роста;
* экономию времени;
* конкретный результат;

сервис не должен самостоятельно создавать такие цифры.

AI может улучшать формулировку, но не должен превращать предположение в факт.

# 10. UX Principles

Продукт должен следовать нескольким принципам.

### Простота

Пользователь должен понимать, что делать, без инструкции.

### Быстрое создание

Основное портфолио должно собираться без заполнения десятков полей.

### Project-first

Главное внимание уделяется работам, а не длинному разделу «Обо мне».

### Mobile-first

Публичное портфолио должно нормально работать на телефоне.

### Профессиональный внешний вид

Интерфейс должен выглядеть как современный SaaS-продукт, а не как учебный CRUD.

### Контроль пользователя

AI предлагает изменения, но пользователь принимает окончательное решение.

---

# 11. Что НЕ входит в MVP

Чтобы проект можно было быстро завершить, следующие функции сознательно откладываются.

### Не делаем сейчас:

* платежи;
* подписки;
* marketplace портфолио;
* социальную сеть;
* лайки;
* комментарии;
* чат пользователей;
* командные аккаунты;
* сложную аналитику;
* собственный домен для каждого пользователя;
* несколько десятков шаблонов;
* мобильное приложение;
* полноценный drag-and-drop website builder;
* автоматическую публикацию во все социальные сети;
* сложную SEO-платформу;
* платный AI;
* сложную систему ролей.

Эти функции могут появиться в будущих версиях.

# 13. MVP Success Criteria

MVP считается готовым, если пользователь может пройти весь основной путь:

```text
Register
   ↓
Create Profile
   ↓
Create Project
   ↓
Add Project Details
   ↓
Add Links / Image
   ↓
Publish
   ↓
Receive Public URL
   ↓
Another User Opens URL
```

И посетитель без регистрации может:

* открыть портфолио;
* посмотреть профиль;
* посмотреть проекты;
* открыть страницу проекта;
* перейти на GitHub;
* перейти на Live Demo;
* открыть контактные ссылки.

---

# 14. Technical MVP Boundaries

На этапе MVP приоритет:

1. Рабочая авторизация.
2. Надёжное хранение данных.
3. CRUD проектов.
4. Публичные страницы.
5. Загрузка изображений.
6. GitHub integration.
7. AI assistance.
8. Responsive UI.
9. Базовые тесты.
10. Dockerized запуск.

Визуальная полировка выполняется после завершения основной функциональности.

---

# 15. Product Principle

Главное правило проекта:

> **Не строить огромный конструктор сайтов.**

Мы создаём **быструю платформу для профессионального представления реальных проектов**.

Вторая ключевая идея:

> **Проект пользователя важнее шаблона.**

Дизайн должен помогать показать работу, а не отвлекать от неё.

Третья:

> **AI помогает оформить информацию, но не придумывает достижения пользователя.**

# 18. Final Product Definition

**Portfolio Platform** — это сервис, который позволяет разработчику или фрилансеру собрать свои проекты в одном месте, профессионально оформить их как кейсы и получить публичное портфолио по одной ссылке.

Минимальная ценность продукта:

> **«У меня есть несколько проектов → я добавляю их в сервис → получаю профессиональную страницу → отправляю одну ссылку клиенту или работодателю».**

AI, GitHub-интеграция и дополнительные возможности усиливают основной продукт, но не заменяют его.

**MVP должен быть маленьким, законченным и реально работающим.**
